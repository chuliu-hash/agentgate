# 1. 项目介绍与业务问题

## 1.1 先建立业务全景

AgentGate 是一个面向智能体和业务应用的工具开放平台。平台管理员把内部或第三方 HTTP 能力登记成 API；开发者创建应用拿到 AppKey/AppSecret，为应用申请 API 订阅；审批通过后，应用可以用签名请求调用开放 API。平台在请求经过上游之前完成身份、权限、速率和额度检查，并对上游响应做必要脱敏，最后记录调用情况。

可以把它理解为工具调用链路上的治理层：它不执行模型推理，也不负责智能体编排，重点是回答“哪个应用可以调用哪个工具、可以调用多快和多少、数据是否安全、出了问题能否追溯”。

```text
管理员登记并上架 API
        ↓
开发者创建 App，申请 App 对 API 的订阅
        ↓
管理员审批并绑定配额套餐
        ↓
调用方携带 AK、时间戳、Nonce、HMAC 签名请求
        ↓
平台校验身份、IP、API 状态、订阅、QPS 和日/月额度
        ↓
安全检查后转发上游 → 响应脱敏 → 返回 traceId
        ↓
调用日志异步写入，开发者和管理员查看日志/看板
```

## 1.2 面试开场：1 分钟版本

> 我做的是 AgentGate，一个基于 Java 8 和 Spring Boot 的智能体工具开放平台。它把平台侧 API 管理和开发者侧应用接入连起来：管理员维护上游 API、套餐并审批订阅，开发者创建应用后用 AK/SK 签名调用已获批的 API。开放请求会经过过滤器校验签名、时间戳和 Nonce，再检查应用状态、IP 白名单、API 上架状态、订阅和 Redis 中的限流配额，然后由服务层安全地代理到上游。系统还做了敏感字段脱敏、traceId 调用日志、RabbitMQ 异步落库和管理操作审计。技术上使用 MySQL 存业务数据、Redis 做登录态/缓存/限流配额，MyBatis-Plus 访问数据库。当前是单体应用，适合快速部署和演示。

## 1.3 面试开场：3 分钟版本

按“业务问题—关键链路—设计重点—边界”展开，而不是逐个背技术名词：

1. **业务问题**：多个智能体应用要访问不同工具，但上游不应各自实现认证、授权、配额和审计。平台把这些横切能力统一起来。
2. **领域对象**：用户拥有 App；平台定义 API；App 对 API 建立 Subscription；订阅关联 QuotaPlan；调用产生 CallLog，按日聚合到 UsageStat；管理操作写 AuditLog。
3. **开放调用**：`TraceIdFilter` 生成链路标识；`SignatureFilter` 读取可重复请求体，验 HMAC、防重放并检查权限和额度；Controller 取出已验证上下文；代理服务校验目标地址并转发；响应按敏感级别脱敏。
4. **工程设计**：数据库唯一索引处理并发唯一性；状态更新使用“主键 + 旧状态”的条件更新；Redis Lua 用单个脚本原子完成限流与日/月配额扣减；调用日志通过 RabbitMQ 与主请求解耦，并在发送调用抛异常时尝试同步持久化。
5. **边界与改进**：这是单体项目。异步日志没有 Outbox，发送异常兜底不等同于端到端可靠投递；QPS 和配额分别执行，不具备整体原子性；若发展到生产规模，会补齐确认/重试/告警、Outbox 或可靠事件投递，并评估网关独立扩展。

## 1.4 角色与业务模块

| 角色 | 主要动作 | 业务价值 |
|---|---|---|
| 开发者 | 注册登录、创建 App、重置 Secret、维护 IP 白名单、申请订阅、查自己的日志和看板 | 让调用方获得受控的工具访问凭证与用量视图 |
| 管理员 | 管理 API 与套餐、审批订阅、查询全平台调用日志、查看审计和看板 | 控制工具上架、访问准入、商业配额与运营风险 |
| 开放 API 调用方 | 携带 AK、时间戳、Nonce、签名调用 `/openapi/{apiCode}` | 在不直接暴露上游系统的情况下访问获准工具 |

## 1.5 领域模型怎么讲

- `User` 是控制台用户，角色分为管理员和开发者。
- `App` 属于一个用户，保存 AppKey、加密后的 AppSecret、状态与 IP 白名单。
- `ApiDefinition` 描述对外稳定编码、方法、上游 URL、敏感级别和发布状态。
- `Subscription` 关联 App、API 和配额套餐；`(app_id, api_id)` 唯一，避免重复订阅。
- `QuotaPlan` 定义 QPS、日配额、月配额。
- `CallLog` 按 traceId 记录一次开放调用；`UsageStat` 按 App、API、日期累计用量。
- `AuditLog` 记录控制台管理动作，和开放接口调用日志是两种不同审计对象。

## 1.6 常见业务追问

### 为什么需要“订阅审批”，不能只看 App 是否有效？

App 表示调用方身份，不能代表它对所有 API 都有权限。权限粒度是 App 与 API 的关系；Subscription 记录申请、审批状态和套餐。开放请求必须同时满足 App 有效、API 已发布、Subscription 为 `ACTIVE`。

### AppKey 和 AppSecret 有什么区别？

AppKey 是公开的定位标识，用来查找应用；AppSecret 是签名密钥，不应传输。服务端从存储中解密 Secret 后计算 HMAC，只有相同密钥的调用方才能生成匹配签名。Secret 创建/重置时只返回明文一次，数据库存 AES-GCM 密文。

### 为什么要区分调用日志和操作审计？

调用日志回答“哪个 App 在什么时候调了哪个 API、结果如何、耗时多少”；操作审计回答“哪个登录用户执行了上架、审批或配置修改，操作是否成功”。它们的主体、字段、查询入口和保留策略都不同。

### 这个项目为什么是单体？

当前目标是用较低的部署和排障成本展示完整业务闭环；功能边界虽分层，但还没有服务注册、远程调用、分布式事务等微服务基础设施。若调用量和团队规模增长，可以先把开放 API 入口拆成独立网关，并明确配置发布与数据所有权，再逐步拆分管理面和日志消费端。

## 1.7 讲项目时避免的说法

- 不要说“微服务网关”：当前项目是单模块 Spring Boot 单体，`SignatureFilter` 实现部分网关治理职责。
- 不要说“JWT”：登录态是随机 Token 存 Redis，拦截器恢复用户上下文并滑动续期。
- 不要说“消息 exactly-once”：消费者可能重复收到消息，当前靠 traceId 唯一约束和幂等插入避免重复计数。
- 不要说“失败调用不扣额度”：QPS 与日/月配额已在单脚本内原子扣减，但扣减发生在上游调用之前，上游失败仍不退额度。
- 不要说“日志绝不丢”：当前实现有同步兜底、手动 ACK 和死信队列，但没有 Outbox，也未形成完整的自动重试与死信补偿闭环。
